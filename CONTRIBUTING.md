# Contributing to Hyper-Vibe Coding Course

First off, thanks for thinking about contributing! This project is built BY neurodivergent minds, FOR everyone. Your perspective matters. 🧠✨

## Code of Conduct

Please review `CODE_OF_CONDUCT.md` before participating. We're committed to providing a welcoming, harassment-free experience for everyone.

## Ways to Contribute

### 🐛 Report Bugs
Found a bug? Great catch!

1. Check if it's already reported in [Issues](https://github.com/welshDog/Hyper-Vibe-Coding-Course/issues)
2. Use the **Bug Report** template when creating a new issue
3. Include:
   - Steps to reproduce
   - Expected behavior
   - Actual behavior
   - Screenshots (if visual)
   - Your environment (OS, browser, Node version, etc.)

### ✨ Suggest Features
Have an idea? We love hearing them!

1. Check [existing discussions](https://github.com/welshDog/Hyper-Vibe-Coding-Course/discussions)
2. Start a **Feature Discussion** with:
   - What problem does this solve?
   - How does it improve learning for neurodivergent folks?
   - Example use case

### 📝 Improve Documentation
Typos? Confusing sections? Missing guides?

- Documentation PRs are always welcome
- Fix typos, clarify instructions, add examples
- No approval needed for small doc fixes

### 💻 Submit Code

#### Setup
```bash
git clone https://github.com/welshDog/Hyper-Vibe-Coding-Course
cd Hyper-Vibe-Coding-Course
npm install
npm run dev
```

#### Before You Code
1. Check open issues/PRs to avoid duplicate work
2. For larger changes, open an issue first to discuss approach
3. Follow the existing code style

#### Making Changes
```bash
git checkout -b feature/your-feature-name
# or
git checkout -b fix/issue-number-description

# Make your changes...
npm run test     # Run tests
npm run lint     # Check code style

git add .
git commit -m "✨ Brief description of change"
git push origin feature/your-feature-name
```

#### PR Guidelines
- Keep PRs focused (one feature/fix per PR)
- Link to related issues: `Closes #123`
- Add screenshots for UI changes
- Update tests if you changed functionality
- Update documentation if you changed behavior

## Development Guidelines

### Code Style
- Use **ESLint** rules (automatically checked on PR)
- Format with **Prettier** before committing
- Follow existing patterns in the codebase

### Commits
- Use clear, descriptive commit messages
- Start with emoji: `✨` (feature), `🐛` (fix), `📝` (docs), `🔧` (config)
- Example: `✨ Add dark mode toggle to dashboard`

### Testing
- Write tests for new features
- Ensure all tests pass: `npm run test`
- Aim for >80% coverage on new code

### Accessibility (A11y)
- ADHD-friendly: clear labels, visual feedback, reduced motion support
- Dyslexia-friendly: readable fonts, good contrast
- Autistic-friendly: predictable interactions, no surprises, sensory controls
- Run accessibility checker on UI changes
